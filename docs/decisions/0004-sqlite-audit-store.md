# ADR 0004：用可迁移 SQLite 保存项目、模型、运行和结果

- 状态：Accepted
- 日期：2026-07-30

## 背景

MVD 只在进程内保存当前检查结果，无法在重启后审计运行历史，也不能支撑模型版本比较、自然语言查询和 BCF 映射。完整平台仍必须保持零外部服务和 clone 后直接运行。

## 决策

使用 Python 标准库 `sqlite3` 建立本地审计存储。应用启动时按 `schema_migrations` 顺序自动迁移，并登记可重建夹具的项目和模型元数据。每次检查保存唯一 `run_id`、确定性 `execution_id`、版本、耗时、状态计数和逐项证据 JSON。

默认数据库位于 `data/runtime/compliance.db`，也可通过 `IFC_COMPLIANCE_DATA_DIR` 指向其他运行目录。整个运行目录被 Git 忽略。

## 边界

- `execution_id` 表示相同输入和检查器得到的确定性内容身份；
- `run_id` 表示一次可审计的实际执行，因此每次运行都唯一；
- SQLite 是历史 source of truth；内存对象仍用于当前小模型的低延迟投影；
- IFC 原文件、三角网格和受版权保护材料不复制进数据库；
- 迁移只向前执行，遇到比应用更新的 schema 时拒绝启动。

## 影响

优点是无需数据库服务器、事务边界清晰、重启后历史仍在，并可直接支持分页和比较。限制是当前仍为单进程写入，未来大模型后台任务需要独立 writer 或任务进程，但 API 契约无需因此改变。
